# mfile 开发测试经验沉淀

> 项目从 Tauri 2 迁移到 Electron（v0.2.0）过程中的架构决策、踩坑与测试实践。多数经验可迁移到其他 Electron / 桌面应用项目。

## 一、架构决策经验

### 1. 启动闪屏的根治方案：show:false + ready-to-show

WKWebView（Tauri）方案的闪屏尝试过内联 splash、原生 CALayer 双层衔接，始终无法根治——三段内容（原生层/HTML/主界面）配色基准无法完全统一，且系统 webview 有冷启动 7~9s、遮挡暂停渲染等平台行为不可控。**Electron 三行方案一次根治**：

```js
const win = new BrowserWindow({ show: false, backgroundColor: 主题底色 });
win.on('ready-to-show', () => win.show());
```

**经验**：当平台怪癖反复消耗时间时，评估换层的成本 vs 继续打补丁的成本。100MB 体积换「启动行为完全可预期」是划算的（Multica 804MB 同样含 Chromium）。

### 2. 分层架构：三个「单一」原则

- **IPC 契约单一来源**：`commands.js` 集中封装全部命令 ↔ `ipcMain.handle` 一一对应，前端不裸写 `invoke('字符串')`。迁移 Electron 时**只换 `tauri.js` 桥实现（解包 {ok,data|error} 信封），契约层与全部业务模块零改动**——分层的红利在架构切换时兑现。
- **渲染与行为分离**：`render.js` 只产 DOM（`data-*` 标记），交互统一在 `events.js` 事件委托。依赖严格单向（commands → render → nav → actions → events），无循环依赖。
- **动作单一执行路径**：原生菜单 / 页面快捷键 / 右键菜单全部收敛到同一组 actions（菜单经 IPC `menu:action` 下发到 `menu-bridge.js` 分发）。菜单 accelerator 由系统接管，页面 keydown 收不到，天然防双触发。

### 3. 表驱动替代手写重复

文件类型徽标（25+ 类型）用一张表 + 一个生成器，新增类型加一行：

```js
[['doc', 'docx', 'rtf'], '#2b579a', 'W'],   // Office 蓝
[['py', 'pyw', 'ipynb'], '#3776ab', 'py'],   // Python
```

同理：主题/排序/前往目标等多入口配置也收敛为表。

## 二、踩坑记录（按出现频率排序）

| 坑 | 现象 | 解法 |
|---|---|---|
| **Electron API 版本差异** | `shell.trashItems is not a function`（Electron 38 只有单数 `trashItem`） | 写前查本地 `node_modules/electron/electron.d.ts`，不凭记忆 |
| **存量功能从未工作** | 即时过滤从第一版就坏（oninput 从未写 `state.filter`） | E2E 按需求文档逐条固化用例，而非只测新代码 |
| **流式写盘竞态** | 解压完成后立即读文件得到空内容 | 进程 `close` ≠ 数据已 flush；`close` + 写入流 `finish` 双事件交汇才 resolve |
| **透明层拦截鼠标** | splash 淡出中（opacity:0 未 display:none）点击无响应、E2E 框选失效 | 开始淡出即设 `pointer-events: none` |
| **hdiutil 资源忙** | electron-builder 打 dmg 失败 "couldn't unmount disk4" | `hdiutil detach /dev/disk4 -force` 后重跑；残留卷是上次打包未卸净 |
| **验证工具自身不可信** | `screencapture -l<winId>` 对 webview 返回陈旧帧，误判「应用冻结」 | 外观验证用全屏截图；行为验证用 E2E 程序化断言，不依赖截帧 |
| **窗口遮挡暂停渲染** | dev 窗口被正式版/其他窗口完全盖住时动画/rAF 全停（JS 定时器仍跑） | 验证时确保窗口前台；用 PID 激活（`osascript tell application "mfile" activate` 会拉起 /Applications 正式版盖住 dev 窗口） |
| **macOS E2E 无 require** | `app.evaluate(() => require('electron'))` 报错 | Playwright 注入模块作参数：`app.evaluate(({ Menu }) => ...)` |

## 三、测试体系（核心经验）

### 1. 分层与分工

| 层 | 工具 | 测什么 | 速度 |
|---|---|---|---|
| 单元 | `node --test`（零依赖） | IPC 实现层纯逻辑：zip/tar.gz 往返、同名冲突、路径穿越、重命名规则矩阵、复制移动语义 | <1s，随时跑 |
| E2E | Playwright for Electron（`_electron.launch`，免下载浏览器） | 真实 app 全链路：preload→IPC→实现→渲染 | ~1.5min，交付前跑 |

**分工原则**：逻辑分支进单测（快、组合多），用户旅程进 E2E（慢、覆盖连通性）。

### 2. headless：E2E 后台跑不抢焦点

主进程支持 `MFILE_HEADLESS=1`（窗口创建但不 `show()`，渲染/DOM 照常工作，Playwright 走 CDP 不依赖窗口可见）。**边跑测试边干活零打扰**，且可 3 并行。这是桌面 E2E 可持续执行的关键一环。

### 3. 夹具设计：每用例独立临时目录

```js
const dir = fs.mkdtempSync(path.join(os.tmpdir(), 'mfile-e2e-'));
// 预置：普通文件/目录 + tar.gz + gz + zip + 25 个类型样本（空文件，扩展名即类型）
// 用完 fs.rmSync 递归清理
```

用例间零共享状态，才能放心并行。断言用**动态值**（fill 前后行数对比）而非硬编码计数——夹具增删样本不会连环挂测试。

### 4. 程序化断言 > 截图肉眼

每条 E2E 同时断言三层：DOM 状态（`.row.selected` 数量）+ 文件系统结果（`fs.readFileSync` 内容比对）+ UI 反馈（toast 文本）。`expect.poll(() => fs.existsSync(...))` 轮询异步落盘。

**实证价值**——本项目 E2E 抓到的 4 个真 bug，全部是人工回归发现不了的：

1. `shell.trashItems` API 不存在（删除功能整体损坏）
2. 即时过滤存量 bug（自第一版未工作过）
3. 流式解压落盘竞态（时序窗口，手动操作恰好被网络延迟掩盖）
4. splash 透明层拦截鼠标（150ms 窗口期，肉眼几乎不可察觉）

### 5. 选择器经验

- 菜单项用 `data-label` 属性选择器精确匹配：`hasText: '打开'` 会误中「在终端中打开」；textContent 含快捷键提示导致 `^复制$` 正则失败
- 二级菜单操作先 `hover()` 父项展开再点击子项
- `.ctx-sub .ctx-item` 限定作用域，避免父项（含子文本）干扰

### 6. 就绪条件要完整

E2E 启动等待最初只等「loadDir 完成」，结果框选用例的 mousedown 全落在淡出中的 splash 上（透明层拦截）。**就绪条件补上 `#splash` 完全 display:none** 后才稳定。排查方法：页面临时注入探针 listener 打印 target——一发定位。

### 7. 测不到的部分：测通路

原生菜单 Playwright 点不到。拆两层测：
- 菜单结构：`app.evaluate(({ Menu }) => Menu.getApplicationMenu()...)` 断言中文菜单项
- 动作通路：主进程 `webContents.send('menu:action', ...)` 下发 → 断言渲染层真实效果（导航/切主题）

### 8. 固定交付流程

```
功能开发 → npm run test:all（单测+E2E 全过）→ npm run dist
→ 杀旧实例 → cp 到 /Applications → open 启动 → 用户验收
```

每次交付都是「正式安装版」，用户手上的版本永远和代码一致；验收反馈直接对着真实构建。

## 四、快速命令

```bash
npm test               # 单测（<1s）
npm run test:e2e       # E2E（headless 后台，~1.5min）
npm run test:all       # 全量
npm run dist           # 打包 dmg+zip
# Electron 下载慢：ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/ npm install
```
